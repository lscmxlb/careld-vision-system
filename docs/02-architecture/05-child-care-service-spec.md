## 二、业务规则设计

### 2.1 排班规则模型

- **规则区间**：按连续自然日区间（`startDate ~ endDate`）设置一条规则。
- **周类型**：区间内分别配置两组——「周一～周五」与「周六、周日」：
  - 可接待起始时间（`startTime`）
  - 结束时间（`endTime`）
  - 每小时接待人数上限（`hourlyCapacity`）
- **时段推导**：自起始时间起每小时一个可约时段（例：8:30 起始 → 8:30、9:30、10:30…），**禁止** 8:45、9:45 等非整点间隔时段。校验规则：`(endTime - startTime)` 必须为整小时数，生成时段数量 = 小时数。
- **例外日**：区间内可单独指定若干日期为例外日（如节假日），该日不适用区间规则，不生成时段。
- **唯一性约束**：同一日期只能被一条规则覆盖，已设置的日期区间不允许与新规则重叠（含例外日所属区间）。
- **时段存储方案**（决策）：规则保存时**物化生成**每日时段记录（`schedule_slot`），便于并发控制人数上限与家长端查询；例外日设置/规则修改时重建对应日期的时段（已有时段存在预约时不允许修改，或仅允许增加容量，见 2.6）。

### 2.2 预约前置条件（两层门槛）

1. 档案状态为「已审核」；
2. 该儿童「剩余可约次数 > 0」。

两者任一不满足，家长端不展示「立即预约」入口；后端在创建预约时**双重校验**（不信任前端）。

### 2.3 预约约束

| 规则 | 说明 | 校验位置 |
|------|------|----------|
| 时段合法 | 仅可预约排班规则生成的整点间隔时段 | 后端强校验 |
| 满额控制 | 时段已约人数 ≥ 该时段接待上限 → 不可约，前端显示「预约已满」 | 后端事务内 `SELECT ... FOR UPDATE`（或乐观锁）防超卖 |
| 每日限制 | 同一儿童同一天只能有 1 个有效预约（状态 ≠ 已取消） | 后端强校验 |
| 次数扣减 | 预约创建成功时**当场**扣减剩余次数（同一事务） | 后端事务 |
| 医生添加预约 | 医生可在当前时间之后手动添加预约（选儿童→日期→时段），同样校验满额与每日限制，同样扣减次数 | 后端强校验 |

### 2.4 取消 / 爽约规则（可配置）

配置项存储于「预约规则设置」模块，默认值：

| 配置项 | 默认值 | 执行逻辑 |
|--------|--------|----------|
| 家长取消时间窗 | 预约开始前 24 小时之前可取消 | 距预约开始不足 24 小时，家长端取消按钮禁用，后端拒绝 |
| 医生取消时间窗 | 预约开始前 2 小时内可手动取消 | 按语义「预约开始前 2 小时内可取消」（详见待确认项 Q2） |
| 爽约处理 | 由医生选择是否退还 | 预约超时未开始养护时，医生标记「爽约」，弹窗选择是否退还次数 |

取消成功（在时间窗内）**自动退还**剩余次数，与取消在同一事务。

### 2.5 预约 / 养护状态机

```
已预约(1) ──医生点「开始养护」──▶ 养护中(2) ──录入养护后视力──▶ 已完成(3)
   │                                │
   │                                └──开始后超过 1.5 小时未录入──▶ 自动已完成(3)（定时任务）
   │
   ├──家长在时间窗内取消──▶ 已取消(4)（退还次数）
   ├──医生在时间窗内取消──▶ 已取消(4)（退还次数）
   └──超时未到（爽约）──▶ 医生标记爽约 → 已取消(4)（医生选择是否退还）
```

- 状态枚举：`1 已预约 / 2 养护中 / 3 已完成 / 4 已取消`（替代现有 1待到店/2已到店/3服务中/4已完成/5已取消，需做数据迁移映射）。
- 「开始养护」动作：校验当前时间已到预约时段；将状态置为养护中；**同事务创建养护记录**（`care_record`，状态=养护中），医生随即录入养护前视力（左眼/右眼/双眼）。
- 「完成养护」动作：录入养护后视力（左眼/右眼/双眼），养护记录置为已完成，预约置为已完成。
- 超时自动完成：定时任务每 5 分钟扫描「养护中」且 `start_time + 1.5h < now` 的预约，置为已完成（养护后视力留空）。
- 爽约判定：定时任务/医生手动；预约开始后（可配置缓冲）仍未「开始养护」的记录，医生在列表中标记爽约并选择是否退还。

### 2.6 次数体系

- **授予**：医生在档案上添加「服务记录」，输入本次授予次数 N → 剩余可约次数 +N（累计追加，不做核销链）。
- **扣减**：预约成功 -1。
- **退还**：时间窗内取消 +1；爽约由医生决定是否 +1。
- **一致性**：扣减/退还必须与预约状态变更同事务；剩余次数采用「授予记录累计 - 有效扣减」实时计算 + 冗余字段双保险（冗余字段 `remaining_count` 便于列表展示与门槛校验，事务内维护）。

## 四、后端 API 设计（增量）

### 4.1 schedule-service

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/schedule-rules` | 创建排班规则（区间+周类型+例外日），生成时段 |
| GET | `/api/v1/schedule-rules` | 规则列表（分页） |
| PUT | `/api/v1/schedule-rules/{id}` | 修改规则（已有预约时限制，见 2.6 决策） |
| DELETE | `/api/v1/schedule-rules/{id}` | 删除规则（仅无预约时可删） |
| GET | `/api/v1/schedule-slots` | 查询某日期可约时段（含 booked_count，家长端/医生端共用） |
| GET | `/api/v1/schedules/reserves/statistics` | 预约统计：起止日期内每日预约数、完成数 |
| POST | `/api/v1/schedules/reserves/{id}/start` | 开始养护（校验时间，状态→养护中，创建 care_record） |
| POST | `/api/v1/schedules/reserves/{id}/complete` | 完成养护（录入养护后视力，联动 vision-service 或本服务内聚合） |
| POST | `/api/v1/schedules/reserves/{id}/no-show` | 标记爽约（body: `refund: true/false`） |

创建预约 `POST /reserves` 逻辑增强：`childId` 必填 → 校验已审核 + 次数>0 + 时段合法 + 满额 + 每日一约 → 事务内扣次数 + booked_count+1。取消 `POST /reserves/{id}/cancel` 逻辑增强：读取 `appointment_config` 校验时间窗（家长/医生分别取 `parent_cancel_hours` / `doctor_cancel_hours`）→ 事务内退还次数 + booked_count-1。

### 4.2 child-service

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/children/{id}/remaining-count` | 剩余可约次数 |
| POST | `/api/v1/children/{id}/service-records` | 添加服务记录（授予次数） |
| GET | `/api/v1/children/{id}/service-records` | 服务记录列表 |

创建/修改档案增强：携带 `source_type`；医生端创建自动 `auditStatus=已审核` 并记录 `source_user_id`；家长端创建 `auditStatus=待审核`。

### 4.3 vision-service

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/care-records` | 养护记录列表（按儿童查询；医院端/家长端共用同一数据） |
| GET | `/api/v1/care-records/{id}` | 养护记录详情 |

### 4.4 auth-service

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/auth/sms/send` | 发送短信验证码（频控） |
| POST | `/api/v1/auth/sms/login` | 手机号+验证码登录（未注册手机号自动注册家长账号） |
| POST | `/api/v1/auth/staff/login` | 医务人员登录（手机号+密码） |

### 4.5 定时任务（schedule-service）

- **自动完成**：每 5 分钟，扫描状态=养护中且 `start_time + auto_complete_hours < now` → 置已完成。
- **爽约候选**：每小时，标记 `no_show_flag=候选`（开始时间已过且未开始养护），供医生在列表中处理；不做自动取消（由医生决定是否退还）。
