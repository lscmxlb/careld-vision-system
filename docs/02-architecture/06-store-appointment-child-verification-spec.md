# 门店端新建预约 · 儿童核验选择逻辑 规格说明（Spec）

> 日期：2026-09-03
> 版本：v1.0（逻辑已与需求方确认，随文档同步开发）
> 范围：store-web（门店端 `appointment-record` 新建预约）+ child-service（后端）+ store-web child 页建档引导
> 状态：已确认，开发中

---

## 一、背景与问题

### 1.1 现状

门店端「新建预约」弹窗中，儿童选择使用单个远程搜索框（`el-select filterable remote`），
输入任意关键字后调用 `GET /children?storeId=&auditStatus=1&keyword=`，
后端 SQL 仅对 **掩码列** 做 `LIKE` 匹配：

```sql
name_mask LIKE '%#{keyword}%' OR phone_mask LIKE '%#{keyword}%'
```

下拉选项仅展示 `张*明（剩余N次）`。

### 1.2 三个缺陷

| # | 缺陷 | 后果 |
|---|------|------|
| P1 | 库中只存掩码/密文，输入**全名或完整手机号永远搜不到**（掩码中间含 `*`），只能输前缀碰运气 | 店员搜索体验差、命中面过大 |
| P2 | 结果只显示掩码名 + 剩余次数，**无法消歧** | 同名同姓、店员对不上号时容易**选错档案**：扣错孩子的次数、视力/养护记录记到他人名下 |
| P3 | 无任何「家长 ↔ 孩子」关系校验 | 任何人可报名字约掉他人孩子的次数；系统无法确认输入的信息与档案真实对应 |

## 二、决策结论

已确认的关键决策：

| 决策项 | 结论 |
|--------|------|
| 门店预约场景 | 家长带孩子到店为主；家长自助预约走 parent-web（登录态背书，**本次不改**） |
| 主核验方式 | **监护人手机号精确核验**（后端解密 `phone_encrypted` 全等比对；无密文的老数据退化为 `maskPhone(输入) == phone_mask` 兜底） |
| 结果消歧 | 结果列表展示 掩码姓名｜性别｜出生日期｜剩余次数，店员与家长当面口头核对出生日期确认 |
| 查无匹配 | 提供**建档引导**：跳转档案页并预填手机号；并提示「家长端注册需保持登记手机号一致」 |
| 兜底路径 | **保留姓名前缀模糊搜索**，但结果标注「未核验」，选择时二次确认（提醒与家长核对出生日期） |
| 展示规则 | 待审核、剩余 0 次、已禁用的孩子：可见但不可选（灰显 + 标签说明） |

## 三、流程设计

### 3.1 主路径：手机号精确核验（默认）

```
[新建预约] 弹窗 → 儿童选择区
  ① 输入监护人登记手机号（11 位） → 点击「查找」
  ② 后端 GET /children/by-phone 精确核验（限定本店）
  ③ 命中 1..N 个孩子 → 下拉列表逐行展示：
      张*明｜男｜2018-03-12      [待审核] [剩3次]
      （已审核且剩余>0 才可选中）
      └─ 店员与家长口头核对「孩子生日几月几号」→ 选中
  ④ 未命中 → 提示「该手机号未在本店登记儿童档案」+ 两个动作：
      a. [前往建档]：跳转 档案管理 页并自动预填该手机号（门店建档 sourceType=2 提交即过审）
      b. 文案提示：若家长已在家长端登记，请确认报出的手机号与注册手机号一致
  ⑤ 选中孩子后按原流程选日期/时段提交（POST /schedules/reserves/v2，后端校验不变）
```

### 3.2 兜底路径：按姓名模糊搜索（标注未核验）

- 主路径下方提供次级入口「按姓名模糊查找」（可来回切换）。
- 仅搜索 **已审核**（`auditStatus=1`）档案，关键字对 `name_mask` 前缀/片段模糊匹配。
- 每行结果带醒目 **「未核验」** 标签与提示文案：
  `未通过监护人手机号核验，请与家长当面核对出生日期后谨慎选择`。
- 点击选择「未核验」档案时弹出确认框，确认后方可选中；选中后表单字段旁仍可见「未核验」标记。

### 3.3 选择规则（两种路径一致）

| 档案状态 | 展示 | 可选 |
|----------|------|------|
| 已审核 + 剩余次数 > 0 + 启用 | 正常显示 | ✅ |
| 待审核（`auditStatus=0`） | 显示 + 标签「待审核」 | ❌（先去档案页审核） |
| 已驳回（`auditStatus=2`） | 显示 + 标签「已驳回」 | ❌ |
| 剩余次数 = 0 | 显示 + 标签「剩0次」 | ❌ |
| 已禁用（`status=0`） | 不参与搜索 | ❌ |

## 四、接口设计

### 4.1 新增：儿童监护人手机号精确查询

```
GET /api/v1/children/by-phone?phone=13800138000&storeId=1
```

| 参数 | 必填 | 说明 |
|------|------|------|
| phone | 是 | 监护人登记手机号，须 `^1[3-9]\d{9}$` |
| storeId | 否 | 数据权限：门店用户由 `DataScopeHelper.resolveStoreId` 强制为本店 |

**响应**：`Result<List<ChildProfile>>`，元素字段仅包含可对外字段：
`id / name(掩码) / phone(掩码) / gender / birthDate / auditStatus / status / remainingCount / parentName / relation / createdAt`（沿用列表接口的掩码契约，**不含明文、不含密文列**）。

**后端匹配逻辑（ChildServiceImpl.searchByGuardianPhone）**：

1. 取本店启用档案（任意审核状态，`includeDisabled=false`）。
2. 逐条匹配：
   - 有 `phone_encrypted` → `AesUtil.decrypt` 后与输入手机号**全等比对**；
   - 无密文（老数据/种子数据）→ `MaskUtil.maskPhone(输入) == phone_mask` 兜底比对。
3. 命中集合按 `created_at DESC` 排序返回。

> 说明：`phone` 字段语义 = 监护人手机号；一个手机号可对应多个孩子（多孩家庭），由生日/性别消歧。

### 4.2 复用接口（不变）

- `GET /children`（列表/模糊搜索，掩码 LIKE，含 `auditStatus=1` 过滤能力）—— 模糊兜底使用
- `GET /children/search`（TV 用，保持不动）
- 建档：`POST /children`（门店建档自动过审）；审核：`POST /children/{id}/audit`

## 五、前置缺陷修复（随本次开发一并修复）

**child-service `updateProfile` 加密断链**（原实现缺陷）：

- 现状：更新档案时仅把请求中的明文姓名/手机号**直接写入掩码列**（泄漏明文），
  `name_encrypted / phone_encrypted` 永不更新 → 家长改号后精确核验永远匹配旧号。
- 修复：请求中的姓名/手机号在更新前重新执行
  `AesUtil.encrypt → *_encrypted` + `MaskUtil.mask → *_mask`，再 `updateById`（两列缺一不可，保持与 createProfile 对称）。

## 六、store-web 改动点

### 6.1 `views/appointment-record/index.vue`（新建预约弹窗）

- 儿童选择区改造为「手机号查找（默认）+ 姓名模糊查找（切换）」双态；
- 选项行展示 掩码姓名/性别/出生日期/剩余次数 + 状态标签；不可约项灰显；
- 「未核验」档案选中前弹确认框；
- 查无记录展示建档引导（跳转 + 预填）+ 家长端注册提示。

### 6.2 `views/child/index.vue`（建档预填）

- 支持路由参数 `?phone=`：进入页面后自动打开「新建档案」弹窗并预填手机号，
  提示「已从预约流程带入家长手机号，完善信息提交后即可（门店建档自动通过审核）」。

### 6.3 API 封装

- `api/child.ts` 新增 `searchChildrenByPhone({ phone, storeId })` → `GET /children/by-phone`。

## 七、边界场景清单

| 场景 | 行为 |
|------|------|
| 手机号格式错误 | 前端表单校验拦截，后端同样校验返回业务错误码 400 |
| 手机号未登记 | 提示 + 建档引导（预填） |
| 一个手机号多个孩子 | 全部列出，生日/性别区分 |
| 改名/改号后（密文已更新） | 精确核验以最新密文为准；掩码列同步刷新 |
| 老数据无密文列 | 掩码比对兜底（只能证明掩码一致，家长在场场景可接受） |
| 档案待审核/驳回 | 可见不可选，先去档案页审核 |
| 剩余 0 次 / 已禁用 | 不可选/不出现 |
| 模糊搜索误选风险 | 「未核验」标记 + 选择确认框 + 提示文案 |
| 家长端自助预约 | 不改（登录态即家长本人，选自己名下孩子） |

## 八、隐私与安全约束

- 任何接口响应**不得**返回明文姓名/手机号，也不返回密文列；
- 接口仅限门店用户数据范围（本店）；沿用现有无 @RequirePermission 约定，数据范围由 `DataScopeHelper.resolveStoreId` 保证；
- 前端展示字段沿用后端掩码值，不做额外解密。
