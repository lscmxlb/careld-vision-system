## 二、A1：共享 JWT 过滤器 + 用户上下文（TODO #4）

### 2.1 根因
- `CareldMetaObjectHandler.getCurrentUserId()` 返回 `null`，createdBy/updatedBy 永不填充。
- `ChildController.audit` 使用 `@RequestAttribute("userId")`，但无任何过滤器设置该属性 → 审核接口必崩。
- auth-service / user-service 的 `SecurityConfig` 要求 `authenticated()` 却无 JWT 过滤器 → 受保护接口全部 403。

### 2.2 实现（careld-common 新增 3 个类）
| 文件 | 作用 |
|------|------|
| `security/UserContext.java` | ThreadLocal 持有 userId/userType/storeId/deptId |
| `security/AuthenticationSetter.java` | 可选 SPI，供 Spring Security 服务同步安全上下文 |
| `security/JwtAuthFilter.java` | OncePerRequestFilter：解析 Bearer token → 填充 UserContext + request attributes(userId/userType/storeId/deptId) + 经 SPI 写安全上下文 |

`CareldCommonAutoConfiguration` 注册 `JwtAuthFilter` 为 bean（无 Security 服务经 servlet filter 自动生效）并新增 `MybatisPlusInterceptor`（PaginationInnerInterceptor）统一分页。

### 2.3 服务改动
- `CareldMetaObjectHandler.getCurrentUserId()` 改读 `UserContext.getCurrentUserId()`。
- auth / user 的 `SecurityConfig`：`addFilterBefore(jwtAuthFilter, ...)` + 提供 `AuthenticationSetter` bean 设置 `UsernamePasswordAuthenticationToken`。
- user/store/child/schedule/vision/sync 的 `application.yml` 新增 `jwt: secret: ${JWT_SECRET}`（与 auth 一致，无硬编码回退）。
- schedule-service 顺带移除残留的 `StdOutImpl` SQL 日志（dev log 9.4 漏改）。

### 2.4 生效结果
createdBy/updatedBy 自动填充真实 userId；`@RequestAttribute("userId")` 可用；user-service 受保护端点不再 403。
