### 2.3 密码错误被报成“网络错误”

## 三、B：数据库中文乱码根治（重新导入）

### 3.1 根因
`docker exec mysql` 客户端默认 `character_set_client=latin1`（库本身 utf8mb4）。当初用 latin1 连接导入 init 脚本，中文 UTF-8 字节被当 latin1 再编码一遍（双重编码，hex `C3A8C2B6...`）。已存数据是乱的，且每次重导都会复发。

### 3.2 修复
- `deploy/init-scripts/01-init.sql`、`02-test-data.sql` 首行加 `SET NAMES utf8mb4;`（无论用什么客户端导入都强制本会话 utf8mb4）。
- 重建库并导入：`DROP/CREATE DATABASE careld_vision` + `--default-character-set=utf8mb4` 重导 01-init + 02-test-data。一次修好全部中文，并验证上一轮密码哈希/审计列修复一并生效。
- 验证：`SELECT real_name FROM sys_user` 显示“超级管理员”；`store_name` 显示“北京朝阳门店”等。

## 五、D：列表契约统一（根治方案）

发现 admin-web 列表视图用 `res.data.list`（期望拦截器返回完整 Result），但 `request.ts` 拦截器 `return data`（返回内层）；而 store-web 视图用 `res.list`（解包契约）且正常。两套 app 契约相反。正确统一方向是“保持拦截器解包（login/store-web/dashboard 已依赖），把 admin-web 改成 `res.xxx`”，而非翻转拦截器（翻转会反过来搞坏 store-web）。

- **后端**：Store/ScheduleReserves/Vision/Department 的 controller+service 改为 `Result<PageResult<T>>` + `page/size` 参数，对齐已有的 UserController/DeviceController/OperationLogController 模式（`PageResult.of(records,current,size,total)` + `selectPage`）。视力 `childId`、科室 `storeId` 改可选，不传列全部。
- **前端 admin-web**：9 个列表视图 `res.data.list`→`res.list`、`res.data.pagination.total`→`res.pagination.total`；`types/index.ts` 的 `PageResponse<T>` 改回内层 PageResult 形状 `{list, pagination}`。

## 六、E：补漏（验证中发现）

- **vision/child/sync 缺 logic-delete 配置**：这三个服务 `application.yml` 没有 `mybatis-plus.global-config.db-config.logic-delete-*`，MP 用默认 `deleted_at=0` 去匹配，而 DATETIME 列存的是 NULL → 查询静默返回空（接口 200 但无数据）。补上与 user/store/auth/schedule 一致的配置（`logic-delete-field: deletedAt`、`logic-delete-value: "NOW()"`、`logic-not-delete-value: "NULL"`）。重新打包并重启 vision/child/sync 后，视力列表从 0 条恢复为 20 条。
- **vision_test_record 缺 `dept_id` 列**：`VisionTestRecord` 实体有 `deptId` 字段但表无此列 → `Unknown column 'dept_id'`。ALTER + 01-init.sql 建表语句补 `dept_id`。

## 七、F：CLAUDE.md 沉淀规范（防复发）

- **编码**：init 脚本首行 `SET NAMES utf8mb4;`；命令行导入带 `--default-character-set=utf8mb4`；JDBC URL 含 `characterEncoding=utf-8`；容器 `character-set-server=utf8mb4`。
- **审计列**：凡实体继承 `BaseEntity` 的表必须建出 `created_by/updated_by/created_at/updated_at/deleted_at` 五列。
- **逻辑删除配置**：每个微服务 `application.yml` 必须配 `logic-delete-field/logic-delete-value/logic-not-delete-value`，否则 `deleted_at=0` 匹配不到 NULL 致查询返空。
- **列表契约**：列表接口统一返回 `Result<PageResult<T>>` + `page/size`；拦截器返回内层 `data`；视图用 `res.list`/`res.pagination.total`，不得写 `res.data.xxx`；过滤参数 `required=false`。
- **Vite 代理**：每个 `/api/v1/<module>` 必须有显式规则指向对应微服务；兜底 `/api`→8281 仅作 fallback，不可依赖其路由业务接口。
