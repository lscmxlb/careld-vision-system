## 二、前端无法打开问题

## 四、家长端登录失败

### 4.1 问题现象
家长端（5173）登录失败，提示"用户名或密码错误"。

### 4.2 根因分析
前端 `userStore.login()` 发送 `loginType: 1`（用户名登录），但家长端只有手机号输入框，应使用 `loginType: 2`（手机号登录）。

**后端认证逻辑**：
- `loginType: 1` → 调用 `selectByUsername(getUsername())` → 前端未传 username → 失败
- `loginType: 2` → 调用 `selectByPhone(getPhone())` → 前端传了 phone → 成功

### 4.3 修复方案
修改 `frontend/parent-web/src/stores/user.ts` 第 38 行：

```diff
- loginType: 1 // 1=密码登录
+ loginType: 2 // 2=手机号密码登录
```

## 五、ERR_CONNECTION_REFUSED

### 5.1 问题现象
登录后请求 API 报 `post http://localhost:8281/auth/login net::ERR_CONNECTION_REFUSED`。

### 5.2 根因分析
`VITE_API_BASE_URL=http://localhost:8281` 硬编码为绝对地址。当从其他设备访问前端时，浏览器中的 `localhost` 指向那台设备自身，而非服务器。

### 5.3 修复方案
使用 Vite 反向代理：前端 API 请求改为相对路径 `/api/v1`，由 Vite 开发服务器转发到后端。

**修改文件**：
- `frontend/parent-web/.env` — `VITE_API_BASE_URL=/api/v1`
- `frontend/parent-web/.env.development` — `VITE_API_BASE_URL=/api/v1`
- `frontend/parent-web/vite.config.ts` — 添加代理配置

## 六、微服务代理路由

### 6.1 问题现象
登录成功后，请求 `/api/v1/children` 返回 403 Forbidden。

### 6.2 根因分析
Vite 代理将所有 `/api` 请求转发到 auth-service（8281），但 `/api/v1/children` 在 child-service（8284）。Auth-service 的 SecurityConfig 拦截了该请求返回 403。

### 6.3 修复方案
按 API 路径前缀路由到对应微服务：

```typescript
proxy: {
  '/api/v1/auth':        { target: 'http://localhost:8281', changeOrigin: true },
  '/api/v1/users':       { target: 'http://localhost:8282', changeOrigin: true },
  '/api/v1/stores':      { target: 'http://localhost:8283', changeOrigin: true },
  '/api/v1/departments': { target: 'http://localhost:8283', changeOrigin: true },
  '/api/v1/children':    { target: 'http://localhost:8284', changeOrigin: true },
  '/api/v1/schedules':   { target: 'http://localhost:8285', changeOrigin: true },
  '/api/v1/vision':      { target: 'http://localhost:8286', changeOrigin: true },
  '/api/v1/sync':        { target: 'http://localhost:8287', changeOrigin: true },
  '/api':                { target: 'http://localhost:8281', changeOrigin: true }, // 兜底
}
```

**微服务端口映射表**：

| 路径前缀 | 服务 | 端口 |
|----------|------|------|
| /api/v1/auth | auth-service | 8281 |
| /api/v1/users | user-service | 8282 |
| /api/v1/stores, /api/v1/departments | store-service | 8283 |
| /api/v1/children | child-service | 8284 |
| /api/v1/schedules | schedule-service | 8285 |

## 七、添加孩子保存失败（500 错误）

### 7.1 问题现象
添加孩子保存失败，后端返回 500 错误"系统繁忙，请稍后重试"。

### 7.2 根因分析（共 3 个问题）

#### 问题 1：前后端字段名不匹配
- 前端发送：`name`, `phone`
- 后端实体期望：`nameMask`, `phoneMask`
- 结果：反序列化后 `nameMask`/`phoneMask` 为 null

#### 问题 2：AES 密钥长度无效
- 配置密钥 `careld-vision-encryption-key` 为 28 字节
- AES-256 要求 16/24/32 字节
- 结果：加密时 `InvalidKeyException`

#### 问题 3：MyBatis-Plus 字段自动填充缺失
- BaseEntity 标记了 `FieldFill.INSERT`，但没有 `MetaObjectHandler`
- 结果：`created_at`, `updated_at` 显式插入 null → 违反 NOT NULL 约束

### 7.3 修复方案

#### 修复 1：AES 密钥（32 字节）
```yaml
encryption:
  key: careld-vision-encrypt-key-32byte  # 精确 32 字节
```

#### 修复 2：新增 ChildRequest DTO
```java
// backend/careld-child-service/src/main/java/com/careld/child/dto/ChildRequest.java
@Data
public class ChildRequest {
    private String name;       // 匹配前端字段
    private String phone;      // 匹配前端字段
    private Long storeId;      // 门店ID
    private LocalDate birthDate;
    private Integer gender;
    private String eyeCondition;
    // ...
}
```

#### 修复 3：Controller 字段映射
```java
@PostMapping
public Result<Long> create(@RequestBody ChildRequest request) {
    ChildProfile profile = new ChildProfile();
    profile.setNameMask(request.getName());     // name → nameMask
    profile.setPhoneMask(request.getPhone());   // phone → phoneMask
    profile.setStoreId(request.getStoreId() != null ? request.getStoreId() : 1L);
    // ...
}
```

#### 修复 4：MetaObjectHandler
```java
@Component
public class CareldMetaObjectHandler implements MetaObjectHandler {
    @Override
    public void insertFill(MetaObject metaObject) {
        LocalDateTime now = LocalDateTime.now();
        this.strictInsertFill(metaObject, "createdAt", LocalDateTime.class, now);
        this.strictInsertFill(metaObject, "updatedAt", LocalDateTime.class, now);
        // ...
    }
}
```

注册到自动配置：
```java
@Configuration
@Import({GlobalExceptionHandler.class, CareldMetaObjectHandler.class})
public class CareldCommonAutoConfiguration {}
```

## 十三、家长端预约页 Bug 修复

### 13.1 问题现象
1. `/appointment` 页面选择孩子后，姓名、年龄不显示
2. 日期选择器无任何日期可点

### 13.2 根因分析

**问题 1：孩子信息不显示**
- 后端 `ChildProfile` 实体返回字段为 `nameMask`（脱敏姓名）和 `phoneMask`（脱敏手机号）
- 前端模板使用的是 `child.name` 和 `child.age`，字段名完全不匹配
- `age` 字段后端根本不返回，需从 `birthDate` 前端计算

**问题 2：日期无法选择**
- 后端 `/api/v1/schedules/calendar` 返回 `List<Schedule>`（扁平数组）
- 前端 `scheduleApi.getAvailableSchedules` 声明返回类型为 `Record<string, Schedule[]>`（按日期分组的 map）
- `availableDates.value = Object.keys(scheduleMap)` 实际拿到的是数组索引 `["0","1","2"...]`
- `date.substring(8,10)` 等字符串操作在 `"0"` 上返回空值，导致渲染空白

### 13.3 修复方案

**前端修复：**

| 文件 | 修改 |
|------|------|
| `parent-web/src/types/index.ts` | `Child` 接口增加 `nameMask`、`phoneMask` 字段，`name`/`phone` 改为可选兼容 |
| `parent-web/src/views/appointment/index.vue` | 模板中 `child.name` → `child.nameMask \|\| child.name`；新增 `calcAge(birthDate)` 计算年龄 |
| `parent-web/src/api/schedule.ts` | `getAvailableSchedules` 内部将后端扁平 `List<Schedule>` 按 `scheduleDate` 分组为 `Record<string, Schedule[]>`，并补充 `availableCount = maxCapacity - reservedCount` |

**后端修复：**

| 文件 | 修改 |
|------|------|
| `careld-child-service/.../ChildController.java` | `/children` 端点新增 `parentUserId` 查询参数 |
| `careld-child-service/.../ChildService.java` | `listProfiles` 方法签名增加 `parentUserId` |
| `careld-child-service/.../ChildServiceImpl.java` | 透传 `parentUserId` 到 Mapper |
| `careld-child-service/.../ChildMapper.java` | SQL 增加 `AND parent_user_id = #{parentUserId}` 条件 |
