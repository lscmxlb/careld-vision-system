## 一、背景与决策

### 1.1 现状问题（2026-09-15 代码核对）

parent-web 现有 7 个页面：登录、子女档案（profile）、检测报告（report）、视力趋势（trend）、预约养护（appointment，4 步）、我的预约（appointment/list）、养护记录（care-record）、个人中心（mine）。

| # | 模块 | 目标（05 spec 5.2） | 现状 | 差距 |
|---|------|--------------------|------|------|
| 1 | 登录 | 仅手机号 + 短信验证码 | **密码 + 验证码双 Tab** | ✗ 需去密码 Tab；后端 `/sms/send`、`/sms/login` 已就绪 |
| 2 | 档案卡片 | 显示剩余次数/审核状态 + 立即预约门控 | 已显示 `remainingCount`、待审核/已驳回标签、按钮禁用门控与提示 | ✓ 功能已具备，重建时照此实现 |
| 3 | 添加孩子 | 家长添加 → 待审核 | 已有弹窗表单（`childApi.addChild`） | △ 核对字段与 PC 建档一致性、提交后"待审核"提示 |
| 4 | 预约流程 | 去「选择医院」步骤；整点时段；满额禁用；每日一约；扣次数 | 仍为 4 步（**选择医院** → 选择孩子 → 选择时间 → 确认预约）；已接入 `available-dates`/`slots`/`createReservationV2`、有次数前置校验 | ✗ 主流程结构需改；△ 满额禁用、每日一约提示、扣次数成功反馈需补齐 |
| 5 | 我的预约 | 状态枚举同步（含已爽约）；取消按家长时间窗（24h）禁用并提示退还 | 状态映射仅 1–4（**缺 5=已爽约**）；取消仅必填原因，**无时间窗禁用** | ✗ 补状态 5；✗ 时间窗交互 |
| 6 | 养护记录 | 瀑布流卡片：日期+时段、前/后视力、执行人；按儿童筛选 | 页面存在（`getRecordsByChild`） | △ 卡片字段与详情页重建时补齐 |
| 7 | 视力趋势 / 检测报告 | —（数据源待定） | 两页均读**老接口** `visionApi.getVisionRecords`（vision_test_record 旧表） | ✗ 与新体系 `care_record` 脱节，数据源需决策 |
| 8 | 个人中心 | 移除修改密码（纯验证码无密码） | 待核对 mine 页内容 | △ 去掉密码相关入口 |

> 该表作为**功能基线**：重建后的 parent-h5 直接按"目标"列实现，不再继承旧实现的问题。

### 1.2 重建策略

- 新建 `frontend/parent-h5/`（uni-app CLI 工程），页面与功能按改进后目标**直接实现**。
- 老 parent-web **保留运行**至新端 H5 验收通过并完成切换后**下线**（代码归档不删，迁移对照见第五章）。
- 后端零改造：沿用现有全部接口。

## 二、技术选型（uni-app）

| 层级 | 方案 | 说明 |
|------|------|------|
| 框架 | uni-app（Vue 3 组合式 API）+ Vite + TypeScript | 与医生端同一模板（`uni-preset-vue#vite-ts`），两端工程结构/封装可互相参考 |
| UI 组件库 | 与医生端**保持一致**（Q1 一起拍板：uView Plus 3 推荐 / uni-ui） | element-plus 不支持小程序端，不采用 |
| 状态管理 | Pinia | 用户信息、选中儿童等 |
| 路由 | `pages.json`（含 tabBar），`uni.navigateTo/redirectTo/switchTab` | 注意页面栈 10 层限制 |
| 请求层 | `uni.request` Promise 封装（token 注入、统一错误提示、401 跳登录） | 替代 axios |
| 存储 | `uni.setStorageSync`（token） | |
| 图表 | 视力趋势页：qiun-data-charts（ucharts，跨端）或 lime-echart（echarts 的 uni-app 封装） | 待 Q2 拍板趋势页去留后再定 |
| 工程目录 | `frontend/parent-h5/`，H5 开发端口 5177（避开 5172/5175/5176） | 代理配置在 `manifest.json` h5 devServer |
| 打包 | `dev:h5` / `build:h5` / `build:mp-weixin` | 一期发 H5，小程序形态后续编译发布 |

## 三、页面设计（pages.json）

```
frontend/parent-h5/src/pages/
├── login/index.vue           # 登录（纯短信验证码，无 tabBar）
├── child/index.vue           # 子女档案（tabBar 首页）：卡片列表 + 添加孩子弹层
├── appointment/index.vue     # 预约养护（tabBar）：3 步（选孩子 → 选时间 → 确认）
├── appointment/list.vue      # 我的预约（tabBar）
├── care-record/index.vue     # 养护记录（tabBar）：列表 + 详情
├── trend/index.vue           # 视力趋势（二级页，Q2 决策）
├── report/index.vue          # 检测报告（二级页，Q2 决策）
└── mine/index.vue            # 个人中心（tabBar）
```

tabBar 五入口：**档案 / 预约 / 我的预约 / 养护记录 / 我的**（趋势与报告为档案详情内的二级入口，视 Q2 决策调整）。

### 3.1 登录页（P0）

- 仅「手机号 + 短信验证码」：验证码按钮 60 秒倒计时、频控提示（后端已实现频控）。
- `POST /auth/sms/send` 发送，`POST /auth/sms/login` 登录（未注册手机号自动注册家长账号）。
- 登录成功后 token 存 uni storage；无密码概念，个人中心无改密入口。
- 小程序形态二期预留：`#ifdef MP-WEIXIN` 增加 wx.login / 手机号授权快捷登录。

### 3.2 预约养护页（P0，核心改造）

- 流程 3 步：**选择孩子 → 选择时间 → 确认预约**（去掉选医院）。
- **storeId 来源**（Q1 拍板）：建议取所选孩子的 `storeId`（孩子归属门店即预约门店）。
- 选择时间步：
  - 日期横向条复用 `available-dates`（后端已过滤无排班日期）。
  - 时段列表复用 `slots`：满额时段禁用并显示「预约已满」；只展示未来时段。
- 确认步：显示孩子、日期、时段、剩余次数；提示「预约成功将扣减 1 次可用次数」。
- **每日一约**：所选孩子当天已有有效预约时在选择时间步明确提示并禁止提交（后端已强校验，前端提前拦截）。
- 成功后：成功页显示**最新剩余次数**（重新拉取档案刷新）。

### 3.3 我的预约页（P1）

- 状态字典完整：`1 已预约 / 2 养护中 / 3 已完成 / 4 已取消 / 5 已爽约`（爽约红标，注明「次数不退还」）。
- **取消时间窗**：距预约开始不足家长取消小时数（默认 24h，读预约规则配置 `parent_cancel_hours`）时取消按钮置灰并提示；时间窗内取消成功提示「预约已取消，次数已退还」。
- 卡片显示：预约时间、门店、状态、取消原因（已取消时）。

### 3.4 子女档案页（P1）

- 卡片：姓名、性别/年龄、手机号（脱敏）、剩余次数、审核状态标签（待审核/已驳回）。
- 「立即预约」门控：`auditStatus===1 && remainingCount>0`，否则置灰并提示（未审核 / 次数不足文案）。
- 添加孩子弹层字段与 PC 家长可见口径对齐（Q4 拍板），提交后明确提示「已提交，待医院审核」。

### 3.5 养护记录页（P2）

- 列表：按儿童筛选，瀑布流卡片：养护日期 + 实际时段（后端已按开始/完成时间计算）、养护前/后视力（左/右/双眼）、执行医师/助理。
- 详情：`GET /care-records/{id}`，前后视力对比展示。

### 3.6 视力趋势 / 检测报告（P2，Q2 拍板后落地）

- 方案选项（Q2）：
  - A：两页均改读 `care_record`（趋势=历次养护前视力曲线，报告=单次养护前后对比），与养护记录同源；
  - B：报告页下线并入养护记录详情，趋势页保留换数据源；
  - C：维持老数据源不动（不推荐）。
- 推荐 A；趋势图用 qiun-data-charts / lime-echart。

### 3.7 个人中心（P1）

- 展示：手机号（脱敏）、绑定孩子数。
- 移除修改密码入口；保留退出登录。

## 七、验收标准

1. 登录仅验证码可用；新手机号首次登录自动注册。
2. 预约全流程：3 步完成、满额时段不可选、当天已约孩子被拦截、成功后剩余次数正确减少。
3. 取消：时间窗外置灰、时间窗内取消后次数即时恢复；已爽约预约正确展示且注明不退还。
4. 趋势/报告与养护记录数据同源一致。
5. 与 PC 端交叉操作数据一致（家长取消 → PC 列表同步）。
6. 代码全程走 uni.* API 与条件编译规范，`build:mp-weixin` 可编译通过（预留验证）。
