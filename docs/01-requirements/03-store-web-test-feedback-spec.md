### 1.1 关键现状（实现基线）

- 预约状态：1=已预约、2=养护中、3=已完成、4=已取消（爽约 = status 4 + noShowFlag 1）
- `ScheduleServiceImpl.markNoShow`（ScheduleServiceImpl.java:347）现校验：仅 status=1 且**仅预约当天**（4018）可标记爽约
- `ScheduleServiceImpl.cancelReserve`（:115）现校验：院内侧**预约开始时间一过即不可取消**（4006）
- `ScheduleServiceImpl.adjustReserve`（:383）现校验：status=1、目标时段须在未来（4008），**未校验原预约自身是否已逾期**
- `ReserveAutoTask`（每 5 分钟扫描，initialDelay 1 分钟）现仅有"养护中自动完成"；"爽约不自动取消"是现状注释中的既定原则，本次新增自动爽约
- `GET /api/v1/schedules/reserves` 现仅支持单个 `date`（精确匹配），无默认日期过滤
- `appointment_config` 现有 4 个配置：parentCancelHours / doctorCancelHours / noShowBufferMinutes / autoCompleteHours；无预约记录时 `getConfig` 返回内存默认值（不落库）
- `ChildServiceRecord` 实体**无 remainingAfter 字段**，前端弹窗"变更后剩余"列当前恒为空
- 儿童档案 `childCode`（形如 CH1788936913069）在 140px 列宽下折行两行；列表未提供"视力状况/来源"隐藏前的筛选依赖

## 2. 分模块详细需求

### 2.1 预约管理 /schedule

#### 2.1.1 预约详情弹窗（第 1 项，已完成 2026-09-14）

- 去掉「类型」「来源」列
- 「操作人」→「预约人」
- 新增「养护人」列（executorName，未开始养护显示 "-"）

#### 2.1.2 页面布局优化（第 4 项）

**4-1 查询条件行**
- 「日期范围」选择器与「查询」按钮从卡片 body 移到「预约查询」卡片头部（header）右侧，与标题同行
- 汇总数字（预约总数/完成数/取消数）展示不变

**4-2 月份标题与翻月按钮**
- 「预约日历」卡片标题改为动态：`预约日历 - 2026年9月`（`${year}年${month}月`，数字与"年/月"间无空格）
- 「上个月 / 今天 / 下个月」按钮组放入同一卡片头部右侧
- 隐藏 el-calendar 自带头部（内置月份标题与翻月按钮），用 `:deep(.el-calendar__header) { display: none }` 或等价方式
- 翻月按钮通过修改 `currentDate` 驱动日历与原 `fetchCalendar` 数据刷新

**4-3 日历单元格**
- 删除「已过期」按钮
- 过去日期：仅保留「预约详情」，不得落到「添加预约」
- 数值为 `-/-`（无时段）或 `0/0` 时：数值文字与「预约详情」文字均置灰显示（如 #c0c4cc）
- 单元格按钮分支顺序：过去日期 → 仅「预约详情」；`isDayFull` → 「预约详情 + 预约已满」；其余 → 「预约详情 + 添加预约」

**4-4 预约详情弹窗单行显示**
- 现状：时段列 `14:00:00-15:00:00` 在 130px 列宽下折两行（实测行高 63px）
- 目标：每条数据单行显示
- 实现：时段格式化为 `HH:mm-HH:mm`（去掉秒），必要时微调列宽；保证各列内容不折行

### 2.2 预约记录 /appointment-record

#### 2.2.1 逾期处理与自动爽约（第 2 项）

**逾期定义**：`当前时间 > 预约日期 + 时段结束时间`。

**逾期后操作限制（前端，列表操作列）**

| 按钮 | 现状显示条件 | 调整后 |
|---|---|---|
| 开始养护 | status=1 且当天 | 不变（本次不改，见待确认） |
| 预约调整 | status=1 | status=1 且**未逾期**；逾期禁用（hover 提示"已超过预约时段，不可调整"） |
| 标记爽约 | status=1 且当天 | status=1 且**预约日期不晚于今天**（当天或逾期均可补标） |
| 取消预约 | status=1/2（status=2 禁用） | 在现有禁用条件上增加"逾期禁用" |

**后端守卫（防止绕过前端）**
- `adjustReserve`：新增逾期校验 → 新增错误码 4019「预约时段已结束，不可调整，请使用标记爽约」
- `markNoShow`：4018「仅预约当天可标记爽约」调整为「预约日期不得晚于今天」（允许跨天补标），message 同步修改
- `cancelReserve`：现有 4006（预约开始即不可取消）已覆盖逾期场景，逻辑不变（仅前端按钮同步禁用）

**自动爽约（新增能力）**
- 触发规则：`预约日期 + 时段结束时间 + 自动爽约时长（默认 12 小时）` 后仍未处理（status 仍为 1）→ 系统自动标记爽约
- 执行者：`ReserveAutoTask` 新增扫描（沿用 5 分钟 fixedDelay，条件 `status=1 且 时段结束时间+autoNoShowHours < now`）
- 标记内容：status=4、noShowFlag=1、refundFlag=0（**默认不退还次数**，见待确认）、cancelReason「爽约（系统自动标记）」、cancelledAt=now
- 同步动作：释放时段名额（slotId 分支 `decrementBooked` / 旧链路 `decrementReserved`）；写次数流水 changeType=5（爽约不退还，changeCount=0）
- 定时任务无 UserContext：需在 Service 增加 system 级 markNoShow 变体，操作人 ID/姓名留空或写"系统"
- "预约养护时间"口径：暂定 = 时段结束时间（见待确认）

**配置化（"将规则添加到预约规则中"）**
- `appointment_config` 新增列 `auto_no_show_hours`，默认 12
- 迁移脚本：`database/mysql/migration/17-appointment-config-auto-no-show.sql`（注意：MySQL 不支持 ADD COLUMN IF NOT EXISTS；需为存量行补默认值）
- 预约规则设置页新增表单项「爽约自动标记时长（小时）」，默认 12，范围 1–72，风格与现有项一致（el-input-number + tip）
- `ScheduleRuleServiceImpl.getConfig` 无配置默认值需补 `autoNoShowHours=12`

#### 2.2.2 列表默认查询范围（第 3 项）

- 默认（未选日期）：只显示**今天及以后**的预约记录
- 选中具体日期：精确显示该日期（允许查看历史）
- 重置：恢复默认（今天及以后）
- 后端 `listReserves` 新增 `startDate` 参数（`reserve_date >= startDate`）；前端未选日期时传 `startDate = 今天`
- 已知副作用：昨天遗留的"已预约未处理"记录会被默认视图隐藏（12 小时自动标记窗口内可能无法手动补标），见第 6 章边界场景

## 4. 验收标准

1. /schedule 预约详情弹窗：无「类型」「来源」列，有「预约人」「养护人」列；未开始养护的养护人显示 "-"（已完成项，回归验证）
2. /schedule 日期范围与查询按钮位于「预约查询」行右侧；汇总数字正常
3. /schedule 日历标题显示「预约日历 - 2026年9月」格式；「上个月/今天/下个月」在标题行右侧；切换月份数据正确刷新
4. /schedule 无「已过期」按钮；过去日期无「添加预约」；`-/-`/`0/0` 天数值与"预约详情"置灰
5. /schedule 预约详情弹窗每行单行显示（时段格式 HH:mm-HH:mm，行高恢复单行）
6. /appointment-record 默认只显示今天及以后记录；选具体日期显示该日；重置后回到默认
7. 逾期（当前时间 > 时段结束）的记录：「预约调整」「取消预约」禁用；「标记爽约」可用并能成功提交（跨天亦可）
8. 未逾期记录各按钮行为与现状一致
9. 逾期时长超过配置值（默认 12 小时）后，系统自动标记为爽约：status=4、noShowFlag=1、名额释放、流水记录 changeType=5、不退还次数
10. /appointment-config 出现「爽约自动标记时长（小时）」项，默认 12，保存后生效；任务按该值判断
11. /child 操作按钮顺序为：审核（条件）、预约授权、预约记录、养护记录、档案详情、禁用/启用
12. /child 编辑弹窗字段成对同行；主治医师在页面最后一行；按钮为「保存档案」
13. /child 编辑弹窗有未保存修改时，点取消或 × 弹确认；无修改时直接关闭
14. /child 预约授权弹窗顺序：当前剩余 → 开单医师 → 缴费方式 → 缴费金额 → 授权次数 → 备注；缴费方式默认「自费支付」；金额默认 0；次数默认 1
15. /child 预约记录弹窗标题「预约记录详情」；首列为「日期时间」；「可用次数」有值且与剩余次数口径一致（最新一条 = 当前剩余次数）；变更次数与可用次数居中
16. /child 列表：档案编号单行；列顺序含「主治医师」在「儿童姓名」前；无「视力状况」「来源」；「可用次数」列名正确

## 5. 边界场景

| 场景 | 预期 |
|---|---|
| 逾期记录跨天未处理（昨天 22:00 结束的时段） | 默认列表不显示（第 3 项副作用）；12 小时自动标记兜底；窗口期内需通过日期筛选找到后补标 |
| 预约当天、时段未结束，但已超过爽约缓冲分钟 | 维持现状：当天可标记爽约（与 4018 放宽后一致） |
| status=2（养护中）的记录逾期 | 不受影响：自动完成任务按 autoCompleteHours 处理；爽约仅针对 status=1 |
| 自动标记爽约与人工标记并发 | `markNoShow` 先校验 status=1，重复执行时报 4015，不会重复释放名额 |
| 护理记录/流水弹窗中 changeType=5 的记录 | changeCount=0，可用次数回溯计算保持不变 |
| 新缴费方式与历史数据 | 授权弹窗只提供新选项；列表/流水按库中原值展示（自费/医保/其他 仍可见） |
| 日历当月仅有过去日期 | 全部为过去日期 → 只显示「预约详情」，无「添加预约」，无「已过期」 |

## 6. 待确认点

1. **自动爽约是否退还次数**：本文默认「不退还」（refundFlag=0）。若需退还，自动任务需走 changeType=4 退还逻辑
2. **"预约养护时间"口径**：本文按时段结束时间 + 12 小时；另一种口径为时段开始时间 + 12 小时
3. **`0/0` 的触发场景**：当前实现只会产生 `-/-`（capacity=0）与 `0/N`，未见 `0/0`；置灰条件按"无时段或总量为 0"实现即可，如测试另有截图以截图为准
4. **取消预约禁用时机**：本文按"逾期禁用"；后端 4006 实际在"开始时间一过"即拦截，是否同步按开始时间禁用待确认
